# 单卡多样本批处理

训练入口新增可选 `--microbatch 2`，默认仍为1。它把一个更新内每卡原有的两个样本沿 batch 维合并，保留全局 batch=16；不同场景不会互相做注意力。

样本计划、视角课程、每样本独立噪声和扩散时间、时间损失权重、学习率及更新次数均保持。损失先逐样本求 MSE、乘各自权重，再取平均。八卡每卡2样本一次反传与每卡1样本累积2次在数学目标上等价，但 BF16 内核与梯度累加顺序不同，不承诺逐位相同。microbatch必须整除每卡每更新样本数，不自动改变全局batch。

网络输出头时间编码必须是 `[B,1,D]`。此前传 `[B,D]` 时，B=1正常，但 B=2会错误地把两条样本的时间编码广播到 shift/scale 维。`wan_video_multiview.py`已补齐这一维；参数名称、形状、B=1行为均不变。

CPU回归运行 `python -m multiview.tests.test_batching`，覆盖不同扩散时间、损失权重、1～4源、逐样本与合批梯度、旧B=1输出不变。

GPU诊断基于7500步检查点，原生产冻结代码未覆盖。显存能容纳不代表吞吐一定提高；正式使用前应查看当前硬件上的单卡、DDP和完整恢复实测。


2026-11-20独立H10080GB测试：1/2/3源处理两个样本的前反向，原方案分别15.16/29.75/49.20秒，合批18.65/38.01/64.21秒，慢23%～31%；合批分配峰值41.71/57.99/74.26GiB。3源需expandable_segments减少碎片，4源仍OOM。1～3源损失一致，BF16梯度整体相对差约0.33%～0.36%。因此未部署正式训练，也未继续占卡做八卡候选验收。原方案已完整恢复至7502步，随后执行既定评测。
